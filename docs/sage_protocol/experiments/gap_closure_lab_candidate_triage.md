# SAGE Gap-Closure Lab Candidate Triage

Experimental evidence only. Generated tools listed here are not part of protected final evidence unless separately validated and promoted through a reviewed claim process.

## Summary

The best current candidate is now `BridgePack Clean Broad500: State Sequence Preservation Pack`. It is not protected-claim promotion-ready from this branch because it includes experimental actor/router bridge code, but it is strong enough to carry into clean matched formal validation. It passed 500 broad experimental tasks after repairing bridge-name handling and search-required side-effect accounting, with fresh SAGE/candidate execution, 500/500 cached controls, OpenAI response cache disabled, zero runtime exceptions, no observed helper side-effect incidents, and clear natural adoption. Outcome moved from control `0.5949` to SAGE `0.8134`, delta `+0.2185`, relative lift `+36.7%`.

The prior compact high-fit recency/day/contact portfolio remains retained. It is not protected-claim promotion-ready from this branch because its 250/500 evidence is targeted experimental revalidation with prior local output coverage, but it passed 250 and 500 with fresh SAGE/candidate execution, eligible control-cache reuse only, zero runtime exceptions, zero helper side-effect incidents, and clear natural adoption.

The earlier low-frequency recency/selection/action bridge remains a useful design pocket. Per the campaign clarification, rare-task value is retained as potential instead of being fully discounted, but the high-fit scale result shifted the best candidate from a single low-frequency selector to a smaller recombined portfolio.

Follow-on recombination sharpened the diagnosis. Broad bridge packs with best3 or V2.6 did not survive expanded60 routing/adoption, while a selector-only pack did: visible 2, called 2, VNC 0, called-subset outcome +0.2478. A later confirm100 run failed broad outcome and logged one side-effect preservation incident, so the current selector form is not scalable evidence. It remains a critical-gap design pocket requiring repair.

Before the scale continuation, the strongest new retained single-tool signal was `days_between_timestamps`. It filled a real day-distance gap, produced a gate-passing residual all40 diagnostic, and gave the best quality expanded60 outcome backtest in this continuation. It is now a key ingredient in the high-fit scale portfolio rather than the standalone top candidate.

The final external-holdout confirmation stress test did not change that triage. It used the `best3_plus_final_selector_days_pack` on 100 uninspected external-service tasks, but the cohort had no expected helper fit for the retained recency/day-distance tools. All retained helpers were hidden/no-call, primary outcome regressed, and the run is experimental-only because the cohort is external-service contaminated.

The broad500 top-tool-combo stress run changed the next-campaign target. The retained recency/date/contact tools remained useful and safe, but the run did not beat the documented current-code best3 500 lift. The main remaining gap is now the broader side-effect-free action/precondition surface: settings and device state, safe insufficient-information, contact CRUD, reminder CRUD/scheduling, and send-message preconditions.

## Diagnosis Labels Used

- Hidden by routing: `extract_*` and scalar planners on nonmatching families; this was intentional negative-trigger suppression in most cases.
- Visible but not called: recency bridge and field extractors remain the main adoption gap; selector-only confirm100 regressed from VNC 0/2 at expanded60 to VNC 3/5.
- Called with bad arguments / schema mismatch: old recency chain erased selected target when updates were omitted; repaired.
- Output not final-answer-ready: old selector and service extractor often produced intermediate values only.
- Unsafe side-effect risk: dependency/precondition helper caused one incident; broad live pack caused two incidents before pruning; selector-only confirm100 logged one side-effect preservation failure on a remove-reminder case.
- Overlap/interference with best3: full and refined packs produced canonical gains without primary outcome lift.
- True negative value: `next_service_tool_call` current form and broad abstention overlay.
- Next unsupported category: action/precondition feasibility is not a proven helper yet; it is the next design target because it groups the largest broad buckets with little or no effective helper support.

## Promotion Guardrail

No tool is promoted from force-call success alone, and the selector-only expanded60 result is not promoted after confirm100 failure. The BridgePack clean broad500 result is the best retained experimental candidate after the action/precondition continuation, but it is still experimental because it includes branch-only actor/router bridge code and not a locked protected matched validation. The next step is clean formal validation against frozen best3/V2.6, with the bridge dependency explicitly stated and no code or registry changes between matched arms.
